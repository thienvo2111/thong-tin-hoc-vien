# Runbook deploy — Học viên đăng ký học bù buổi đã vắng (ADR 0012)

> Đây là **lệnh để người vận hành tự chạy trên VPS**. Trợ lý không SSH, không deploy, không chạy lệnh trên VPS.

Đưa VPS lên `main` có tính năng học bù. Prod hiện tại: `ab21316`. Lần deploy này gồm mọi commit chưa deploy sau `ab21316`:

Không có prefix route mới (vẫn `/doi-buoi-hoc`, `/hoc-vien`) → **không** cần chạy lại Nginx. Không đổi `.env`.

Học viên đang dùng đổi buổi → làm **sau 22h**. Dự kiến 10 phút. Gián đoạn: backend 3–5 giây lúc `pm2 reload`.
`ADD COLUMN ... DEFAULT` hằng số trên PostgreSQL ≥ 11 không ghi lại bảng → khóa bảng rất ngắn.

Mọi lệnh chạy trên VPS bằng user thường (không sudo). Repo: `~/apps/boi-duong-nls`.

## ⚠️ Cảnh báo dữ liệu

1. Mọi dòng `doi_buoi_hoc` hiện có nhận `loai = 'doi_buoi'` (đúng nghĩa cũ). Mọi khóa có `so_buoi_hoc_bu_toi_da = 0`
   → **học bù TẮT ở mọi khóa** cho tới khi Quản trị nhập số ở ô *Số buổi học bù tối đa mỗi học viên (0 = tắt)*.
   Đổi buổi giữ nguyên hành vi (các khóa đang bật đổi buổi vẫn chạy như cũ).
2. Khi học bù bật và có đề nghị được duyệt: lịch học viên **thêm** buổi học bù (buổi vắng giữ nguyên), sĩ số buổi gốc
   **không giảm**, buổi học bù được cộng; chuyên cần tính có mặt ở buổi học bù cho buổi đã vắng.
3. Quay lui code: code cũ không biết cột mới → không lỗi; nhưng đề nghị `hoc_bu` (nếu đã có) sẽ bị code cũ hiểu là
   **đổi buổi** → phải tắt học bù và xử lý trước (mục 7).

## 1. Ghi lại trạng thái + backup (TRƯỚC khi deploy)

```bash
cd ~/apps/boi-duong-nls
git rev-parse --short HEAD | tee ~/truoc-deploy-hoc-bu-$(date +%F).txt     # kỳ vọng ab21316
git status --short
export DB_URL="$(grep '^DATABASE_URL=' backend/.env | cut -d= -f2- | tr -d '"' | sed 's/?.*//')"
(umask 077; pg_dump "$DB_URL" -Fc -f ~/backups/postgres/truoc-hoc-bu-$(date +%F-%H%M).dump) && ls -lh ~/backups/postgres/ | tail -3
psql "$DB_URL" -c "SELECT trang_thai, count(*) FROM doi_buoi_hoc GROUP BY 1 ORDER BY 1;" | tee ~/truoc-hoc-bu-dem.txt
unset DB_URL
```

Mật khẩu lấy từ `DATABASE_URL` trong `backend/.env` (bỏ đuôi `?schema=public` vì `pg_dump`/`psql` không nhận) —
**không** dùng `-U` để tránh bị hỏi mật khẩu. File dump phải có dung lượng hợp lý (không 0 byte).
`git status` có file sửa trên VPS → `git stash` trước bước 2, `git stash pop` sau đó.

## 2. Kéo code + kiểm tra migration chờ

```bash
git pull origin main && git log --oneline -1
cd backend && npx prisma migrate status
```

Kỳ vọng chỉ còn đúng 1 migration chưa áp:

```
20261019120000_hoc_bu
```

Thấy migration lạ hoặc báo drift → **DỪNG**.

## 3. Deploy

```bash
cd ~/apps/boi-duong-nls/scripts/vps
bash 06-deploy.sh 2>&1 | tee ~/deploy-hoc-bu-$(date +%F-%H%M).log
```

Script: `npm ci` → `prisma generate` → build → `migrate deploy` → `pm2 reload` → build frontend → chép asset → thay
`index.html`. (Script không reload được Nginx khi không có sudo — lần này không cần.)

## 4. Kiểm tra sau deploy

```bash
export DB_URL="$(grep '^DATABASE_URL=' ~/apps/boi-duong-nls/backend/.env | cut -d= -f2- | tr -d '"' | sed 's/?.*//')"
psql "$DB_URL" -c '\d doi_buoi_hoc'                                                         # có cột loai loai_doi_buoi not null default 'doi_buoi'
psql "$DB_URL" -c "SELECT loai, count(*) FROM doi_buoi_hoc GROUP BY 1;"                   # chỉ 1 dòng: doi_buoi = tổng số đề nghị cũ
psql "$DB_URL" -c "SELECT trang_thai, count(*) FROM doi_buoi_hoc GROUP BY 1 ORDER BY 1;"  # khớp ~/truoc-hoc-bu-dem.txt
psql "$DB_URL" -c "SELECT count(*) FROM khoa_boi_duong WHERE so_buoi_hoc_bu_toi_da <> 0;" # kỳ vọng 0
psql "$DB_URL" -c "SELECT migration_name, finished_at FROM _prisma_migrations WHERE migration_name = '20261019120000_hoc_bu';"
pm2 logs boiduongnls-backend --lines 100 --nostream
unset DB_URL
```

- `SELECT loai, count(*)` chỉ có `doi_buoi`, tổng bằng số dòng trước deploy (không mất, không thêm dòng).
- Không có khóa nào bật học bù. `pm2 logs` không có lỗi lặp lại.
- Đổi buổi vẫn chạy: người hỗ trợ mở menu **Đổi buổi** thấy danh sách như trước (thêm bộ lọc **Loại**).

## 5. Bật học bù cho khóa nào

Quản trị → trang khóa → ô **Số buổi học bù tối đa mỗi học viên (0 = tắt)** → nhập số (ví dụ `1`) → **Lưu số buổi học bù**.
Báo người hỗ trợ cụm trước (hướng dẫn `docs/huong-dan-doi-buoi-ho-tro.md` mục 6; gửi học viên mục *Đăng ký học bù* trong
`docs/huong-dan-doi-buoi-hoc-vien.md`).

> Nên thử trên khóa thử trước: học viên thử vắng 1 buổi → thấy dòng *Đăng ký học bù buổi này?* → gửi → duyệt → lịch có
> thêm buổi nhãn **Học bù**, buổi vắng vẫn vắng; trang lớp gốc vẫn có học viên đó (nhãn *Học bù tại …*), lớp đích có
> *Học bù từ …*; bảng điểm danh lớp đích sửa được ô buổi học bù. Đúng hết mới bật cho khóa thật.

## 7. Quay lui (nếu cần)

Ưu tiên **tắt học bù**: đặt `so_buoi_hoc_bu_toi_da = 0` ở các khóa (dừng đề nghị mới, giữ dữ liệu; đổi buổi không ảnh hưởng).

**Cách A — chỉ quay lui code.** Chỉ an toàn khi **chưa có** dòng `loai = 'hoc_bu'` (code cũ sẽ coi học bù là đổi buổi):

```bash
export DB_URL="$(grep '^DATABASE_URL=' ~/apps/boi-duong-nls/backend/.env | cut -d= -f2- | tr -d '"' | sed 's/?.*//')"
psql "$DB_URL" -c "SELECT count(*) FROM doi_buoi_hoc WHERE loai = 'hoc_bu';"   # phải = 0
unset DB_URL
# Máy dev: revert merge commit trên main rồi push; VPS:
cd ~/apps/boi-duong-nls && git pull origin main && cd scripts/vps && bash 06-deploy.sh
```

Có dòng `hoc_bu` → **dừng**, báo kỹ thuật (cần quyết định từ chối/hủy các đề nghị học bù trước khi quay lui).
`prisma migrate status` sau quay lui có thể báo migration "applied but missing" — bình thường.

**Cách B — gỡ hẳn schema** (spec §1; chỉ sau khi code cũ đã chạy và **không có** dòng `hoc_bu`). Một transaction để
`_prisma_migrations` khớp schema:

```bash
export DB_URL="$(grep '^DATABASE_URL=' ~/apps/boi-duong-nls/backend/.env | cut -d= -f2- | tr -d '"' | sed 's/?.*//')"
psql "$DB_URL" -v ON_ERROR_STOP=1 <<'SQL'
BEGIN;
DO $$ BEGIN
  IF EXISTS (SELECT 1 FROM doi_buoi_hoc WHERE loai = 'hoc_bu') THEN
    RAISE EXCEPTION 'Còn đề nghị học bù — không gỡ';
  END IF;
END $$;
ALTER TABLE doi_buoi_hoc DROP COLUMN loai;
ALTER TABLE khoa_boi_duong DROP COLUMN so_buoi_hoc_bu_toi_da;
DROP TYPE loai_doi_buoi;
DELETE FROM _prisma_migrations WHERE migration_name = '20261019120000_hoc_bu';
COMMIT;
SQL
unset DB_URL
```

(`DROP COLUMN so_buoi_hoc_bu_toi_da` gỡ luôn CHECK `chk_khoa_so_buoi_hoc_bu`.)

**Khôi phục từ backup** (chỉ khi dữ liệu bị sai — mất mọi thay đổi từ lúc dump). Bản dump mục 1 là `-Fc`, dùng `pg_restore`. **Phải quay lui code về commit trước deploy (`git checkout <commit-cũ>` + build) TRƯỚC khi restore**, nếu không code mới sẽ chạy trên schema cũ (thiếu cột `loai`):

```bash
export DB_URL="$(grep '^DATABASE_URL=' ~/apps/boi-duong-nls/backend/.env | cut -d= -f2- | tr -d '"' | sed 's/?.*//')"
pm2 stop boiduongnls-backend
pg_restore -d "$DB_URL" --clean --if-exists ~/backups/postgres/truoc-hoc-bu-<ngay-gio>.dump
pm2 start boiduongnls-backend
unset DB_URL
```
